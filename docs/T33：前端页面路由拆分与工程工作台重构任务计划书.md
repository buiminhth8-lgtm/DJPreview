# T33：前端页面路由拆分与工程工作台重构任务计划书

## 1. 背景

当前 ai-music-mvp 前端已经不再只是一个简单的“一句话生成音乐”页面，而是逐步包含了：

- 一句话生成
- 风格模板选择
- MusicSpec 查看
- MIDI 生成
- WAV 渲染
- SoundFont 选择
- FluidSynth / fallback renderer 状态
- 工程导入导出
- 工程版本管理
- 工程恢复
- Piano Roll / MIDI 预览
- 自然语言编辑
- 渲染任务进度
- 质量报告
- stems 导出
- 工程删除

如果继续把这些功能堆在一个页面里，会导致：

- 页面过长
- 状态混乱
- 生成流程和工程编辑流程互相污染
- 组件难以复用
- 后续 MIDI 编辑器、版本 diff、任务中心难以扩展
- 用户难以区分“新建音乐”和“编辑已有工程”

因此下一阶段需要把前端从“单页面工作台”升级为“创作入口 + 工程库 + 工程工作台”的结构。

---

## 2. 总体目标

T33 的目标不是重写前端，而是完成一次低风险、可持续演进的结构重构。

核心目标：

1. 引入清晰路由。
2. 拆分页面职责。
3. 拆分生成状态和工程工作台状态。
4. 把可复用功能抽象成 feature 模块。
5. 保留现有生成、试听、渲染、SoundFont、版本等能力。
6. 为后续 MIDI 深度编辑、工程库管理、任务中心扩展打基础。

---

## 3. 推荐页面结构

最终推荐路由：

```text
/create
/projects
/projects/:songId
```

如果当前项目暂时不想做三页完整导航，可以先让 `/` 默认跳转到 `/create`。

### 3.1 `/create`：创作页

职责：

- 一句话生成音乐
- 选择基础风格 / 风格模板
- 设置生成强度等参数
- 显示生成中的状态
- 显示新生成工程的简要概览
- 提供“进入工程工作台”按钮
- 显示 SoundFont / renderer 简要状态，但不承担深度音源管理

不建议在此页面放：

- 深度 Piano Roll
- 版本 diff
- stems 详情
- 工程恢复
- 复杂 MIDI 编辑

### 3.2 `/projects`：工程库页

职责：

- 显示历史工程列表
- 搜索 / 过滤工程
- 查看工程基础信息
- 打开工程
- 删除工程
- 导入 `.aimusic.zip`
- 导出工程，可选
- 显示工程最近状态，例如是否有 MIDI / WAV / SoundFont / fallback warning

不建议在此页面放：

- 深度 MIDI 编辑
- 自然语言修改面板
- 复杂版本对比

### 3.3 `/projects/:songId`：工程工作台页

职责：

- 查看当前工程详情
- 试听 WAV
- 查看 MIDI / Piano Roll
- 重新生成 MIDI
- 重新渲染 WAV
- 选择 SoundFont
- 查看 renderer 状态
- 查看 / 恢复版本
- 自然语言编辑工程
- 查看质量报告
- 查看渲染任务
- 导出 MIDI / WAV / stems / `.aimusic.zip`
- 可选：删除当前工程，但必须二次确认

这是后续主要的编辑页面。

## 5. 推荐目录结构

目标结构：

```text
apps/web/src/
├─ app/
│  ├─ App.tsx
│  ├─ router.tsx
│  └─ layout/
│
├─ pages/
│  ├─ CreatePage.tsx
│  ├─ ProjectLibraryPage.tsx
│  └─ ProjectWorkspacePage.tsx
│
├─ features/
│  ├─ generation/
│  ├─ projects/
│  ├─ workspace/
│  ├─ midi/
│  ├─ audio/
│  ├─ soundfonts/
│  ├─ versions/
│  ├─ tasks/
│  ├─ quality/
│  └─ export/
│
├─ shared/
│  ├─ components/
│  ├─ hooks/
│  ├─ types/
│  ├─ utils/
│  └─ constants/
│
└─ api/
   ├─ httpClient.ts
   └─ errors.ts
```

原则：

- `pages/` 只负责页面组合，不写大量业务逻辑。
- `features/` 按业务域组织组件、hooks、api wrapper。
- `shared/` 放真正通用的 UI 和工具。
- `api/` 放底层请求封装和错误处理。
- 不要把所有东西继续堆在 `App.tsx`。
- 不要过度抽象成万能组件。

## 6. 状态管理规划

当前阶段不建议立刻引入 Redux。优先使用：

```text
React Router
feature hooks
局部 useState / useReducer
必要时 Context
```

推荐 hooks：

```text
useGenerateSong()
useProjects()
useProject(songId)
useProjectWorkspace(songId)
useSoundfonts(songId)
useRenderTasks(songId)
useVersions(songId)
useAudioPreview(songId)
useMidiData(songId)
useQualityReport(songId)
```

### 6.1 `/create` 状态

```text
prompt
styleTemplateId
styleStrength
generationOptions
isGenerating
generatedSongId
generatedProjectSummary
recentProjects
generationError
```

### 6.2 `/projects` 状态

```text
projects
searchKeyword
filterStatus
selectedProjectId
deleteDialogState
importDialogState
isLoadingProjects
projectListError
```

### 6.3 `/projects/:songId` 状态

```text
songId
projectDetail
musicSpec
midiInfo
audioInfo
currentVersion
versions
renderTasks
soundfontSelection
rendererStatus
qualityReport
activeWorkspaceTab
workspaceError
```

关键原则：

- 生成页状态不应污染工程工作台。
- 工程库状态不应依赖当前生成 prompt。
- 工作台以 `songId` 为唯一核心上下文。
- 刷新 `/projects/:songId` 后应能重新加载工程详情。

让前端清楚显示当前工程到底使用 fallback 还是 FluidSynth / SoundFont。

## 功能

```text

FluidSynth 是否可用
```


## 验收标准

- FluidSynth 可用时页面能显示。

- 选择 SoundFont 后提示重新渲染。

## 9. 风险与控制

### 风险 1：一次性重构过大

控制方式：

```text
严格按 T33.0 → T33.9 切片执行
每个切片单独 build
每个切片单独 commit
```

### 风险 2：路由切换导致旧状态丢失

控制方式：

```text
工作台以 songId 为核心
刷新页面时重新拉取 project detail
不要依赖 create 页面内存状态
```

### 风险 3：复用过度导致组件复杂

控制方式：

```text
先迁移，再抽象
只抽真正重复且语义一致的组件
不要创建万能组件
```

### 风险 4：工程删除误触

控制方式：

```text
必须二次确认
删除后跳转 /projects
删除中禁用按钮
失败时保留原状态
```

### 风险 5：SoundFont 状态误报

控制方式：

```text
前端不自行判断是否 fallback
以后端 audio_metadata / render result 为准
```
